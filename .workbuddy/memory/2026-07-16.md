## Bark 实际推送验证（解决 413）
- 实测：`.env` 配 `BARK_URL=https://api.day.app` + `BARK_DEVICE_KEY=p6tv2BL4n6GKyvAGYMzqvS`，走代理 `HTTP_PROXY=http://127.0.0.1:10809` 到 api.day.app。
- 短消息(<5KB)返回 200、手机收到；整篇报告 8992 字节（文件 CRLF=9222，Python 读 LF 后 8992）首推报 **HTTP 413**（nginx 单条上限）。
- 根因：官方 api.day.app 真实上限低于 ~5KB（非此前估的 8KB）。首次加自动分片默认 7000 仍 413（chunk1=6971 超）；二次把 `BARK_MAX_BODY_BYTES` 默认降到 **4000** 后，报告拆成 3 条（3994/3990/1006 字节），全部 200，手机收到 3 条「标题 (i/3)」。
- 推送脚本（proven）：
  ```bash
  cd G:/daily_stock_analysis && HTTP_PROXY=http://127.0.0.1:10809 HTTPS_PROXY=http://127.0.0.1:10809 \
    .venv/Scripts/python.exe - <<'PY'
  import sys; sys.path.insert(0, ".")
  from src.notification import NotificationService
  content = open("reports/report_20260716.md", encoding="utf-8").read()
  ns = NotificationService()
  print("BARK_SEND_OK:", ns.send_to_bark(content, title="📈 股票分析报告 - 2026-07-16"))
  PY
  ```
- `docs/CHANGELOG.md` [Unreleased] Bark 条补充分片说明（默认 4000，规避 ~5KB 上限）。
- 结论：Bark 官方服务器链路打通，长报告自动分片可达；后续无外网需求可换自建 bark-server（Tailscale/frp），改 `BARK_URL` 即可，分片阈值用 `BARK_MAX_BODY_BYTES` 调高。
